## 阶段 0 一句话结论

把「审批流」重建为 **「层级 = 一组投票人」** 的执行模型：

```
发起 → [第 1 层：N 人投票] --通过--> [任务群：分配/协作/验收] --完成--> [第 2 层：M 人投票]
                                                    |                              |
                                                    | 任务阻塞/逾期                  | 平票/驳回/超限
                                                    v                              v
                                              [上报到上级部门] <--------------------+
                                                    |
                                    上级：受理 / 退回 / 补充 / 上级投票 / 派任务 / 再上报 / 终审
                                                    |
                                              结果回写原流程（继续 / 退回 / 终审 / 关闭）
```

三层引擎分别负责：**计票（谁同意算通过）**、**任务（通过之后谁干什么）**、**上报（搞不定往上交给谁）**。

## 关键设计决策（D1–D10，已随阶段 0 冻结）

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 用 **物化路径** `Department.path` 而非闭包表存组织树 | 上级/下级查询一条 `LIKE '/1/3/%'` 即可，单机部署不需要闭包表的写放大 |
| D2 | 节点投票规则与投票人解析规则**分表**（`NodeVoteRule` / `NodeVoterRule`） | 一个节点可以「按角色 + 按部门 + 指定人」混合出投票人 |
| D3 | 流程实例创建时**快照投票人**（`InstanceNodeVoter`）而不是投票时实时解析 | 组织变动不能改变已开始流程的投票人集合，且审计可追溯「为什么是这些人」 |
| D4 | 计票结果落 **`VoteResult` 快照**（含原始计数与加权分 JSON） | 规则或组织后续变化不影响历史结论，报表可复现 |
| D5 | 通过规则与否决规则**同时生效、否决优先** | 支持「多数通过，但任一票否决即驳回」这类真实场景 |
| D6 | 所有跨表副作用走 **OutboxEvent**，不直接发 MQ | 状态变更与事件投递同事务，避免「库改了但通知没发」 |
| D7 | 上报默认**冻结原流程**（可配置），解冻时恢复冻结前状态 | 上报期间继续投票会产生两套互相冲突的结论 |
| D8 | 附件默认**本地磁盘 + volume**，通过 storage 接口可切 MinIO/S3 | 满足「单机一台机器部署」的首要目标 |
| D9 | 实时通道用 **Socket.IO**（自带房间/重连/降级），同时保留 SSE 只读进度端点 | 房间语义与 `instance:{id} / dept:{id} / user:{id}` 天然对应 |
| D10 | 生产**不引入 Nginx/K8s/Prometheus**，HTTPS 交给 Caddy 或托管平台 | 直接来自用户约束 C8 |

## 已确认规则清单（阶段 0 冻结基线）

> Q1–Q27 全部闭环。本节是阶段 1 建表、阶段 2/3 实现的**唯一口径**；后续若要改，先改本节再改代码。

### A. 投票机制

| # | 规则 | 取值 |
| --- | --- | --- |
| A1 | 投票组织方式 | 每一层由一组人投票；5 通过规则 + 3 否决规则，**否决优先** |
| A2 | 弃权 | **不允许**，`VoteDecision` 只有 `APPROVE / REJECT` |
| A3 | 必须表态 | **池内每个投票人都必须表态**，未全员表态不得进入结论阶段 |
| A4 | 改票 | **结论形成前可反复更改**、不限次数；历史全留，计票只取最新 |
| A5 | 否决与表态的冲突 | 一票否决只**锁定「不予通过」**，仍等全员表态完（`vetoTerminates=false`） |
| A6 | 平票 | **报上级组织裁定**（`TiePolicy=ESCALATE`）→ 触发上报 |
| A7 | 超时未表态 | 催办 3 轮（间隔 8h）→ 仍未表态则上报；**禁止超时自动通过** |
| A8 | 缺席 | **不算票、不计入投票池**；有委托则受托人投票、仍计入池内 |
| A9 | 法定人数 | `minQuorum=0.6`：池内人数 < 应投票人数 × 60% → 本层不得通过，直接上报 |
| A10 | 人工结论 | 每层必须人工填写结论；默认 `MANUAL_CONFIRM`（确认或改判，改判须填理由） |
| A11 | 结论填写人 | 默认本部门**工号主责人**，无工号则回退部门负责人 |
| A12 | 截止时间 | **自然日**（`CALENDAR_DAY`），不需要节假日日历 |

### B. 可见性

| # | 规则 | 取值 |
| --- | --- | --- |
| B1 | 投票人可见范围 | **只能看到本部门**的投票明细（姓名 + 选择） |
| B2 | 跨部门 | 只给聚合计数（已表态 N/M、同意数、反对数），不含姓名 |
| B3 | 上级部门 | 上报链上的上级部门及其工号成员**可见全部层级投票明细** |
| B4 | 匿名模式 | `ANONYMOUS` 只返回是否已投，不影响计票 |

### C. 流程推进

| # | 规则 | 取值 |
| --- | --- | --- |
| C1 | 层通过后 | 按 `NodeTaskTemplate` 创建任务；任务完成再推动下一层 |
| C2 | 最后层通过 | 流程 `APPROVED`（**停留态**，同时写 `endedAt`）；任一层驳回则 `REJECTED`。归档 `CLOSE → CLOSED` 改为后续显式动作 / 归档任务触发（2026-09-26 调整：定局即归档会让发起人与前端看不到结果态；状态机该路径仍保留） |
| C3 | 冻结 | 上报即**冻结**原流程：计时暂停，投票与任务均不可操作 |
| C4 | 解冻 | 上级意见回写后解冻，恢复冻结前状态与剩余时间 |
| C5 | 状态变更 | 一律走领域服务 + `AuditLog` + `OutboxEvent` + WebSocket 广播 |
| C6 | 重投轮次 | 同层重开投票用 `InstanceNode.round` 区分，历史结论不覆盖 |

### D. 上报（含部门工号）

| # | 规则 | 取值 |
| --- | --- | --- |
| D1 | 触发源 | 手动 / 超时 / 平票 / 连续驳回 / 金额风险超限 / 跨部门争议 / 权限不足 / 任务阻塞 / 任务逾期 |
| D2 | 越级 | **不允许**；只能「直接上级」或沿 `Department.path` **逐级上溯一级** |
| D3 | 投递对象 | **上级部门的工号**（`Department.workNo`），不投给个人；1 部门 = 1 工号 |
| D4 | 工号成员 | 显式指定（`DepartmentWorkNoMember`）；**成员即该级投票人**，各持 1 票 |
| D5 | 工号主责人 | `isPrimary` 只决定"谁默认填结论"，不决定"谁才有票" |
| D6 | 上级处理方式 | **再跑一次同样的投票**（同计票规则、同全员表态、同人工结论），**无单人裁定** |
| D7 | 上级投票节点 | 复用 `InstanceNode` 挂在原实例下（`escalationId` 回指），不新建投票体系 |
| D8 | 意见回写 | 结论含 `CONTINUE / RETURN / REQUEST_MORE / FINAL_APPROVE / FINAL_REJECT`；**不通过默认 `RETURN`** |
| D9 | 僵局 | 上级投票平票 / 超时 / 结论超时 → **`UPGRADED` 再上一级继续投票**，直至 `maxLevel` |
| D10 | 工号缺失 | `onMissingWorkNo=ESCALATE_UP`（继续上溯找有工号的部门）/ `NOTIFY_ADMIN` / `BLOCK` |

### E. 任务

| # | 规则 | 取值 |
| --- | --- | --- |
| E1 | 分配算法 | 手动 / 角色 / 部门 / 投票组 / 负载均衡 / 抢单 |
| E2 | 角色约束 | 每任务**恰好一个 `OWNER` + 恰好一个 `ACCEPTOR`** |
| E3 | 依赖 | 依赖未完成 → `BLOCKED`；依赖完成自动解锁并通知 |
| E4 | 逾期 | 定时扫描；通知 + 可选按规则上报；`overdueNotifiedAt` 防重复 |
| E5 | 上级整改 | 上级不做独立派任务；由投票结论携带行动要求，回写后由原流程生成任务 |

### F. 组织、权限、审计

| # | 规则 | 取值 |
| --- | --- | --- |
| F1 | 组织树 | 物化路径 `Department.path`，前缀查询上下级 |
| F2 | 数据范围 | 本人 / 本部门 / 本部门及下级 / 指定部门 / 全租户 |
| F3 | 越权响应 | 详情越权返回 **404**（不暴露存在性） |
| F4 | 投票记录 | 只 INSERT，不可改不可删；改票用 `isReplaced` 链式留痕 |
| F5 | 审计 | 全量写操作记 before/after，含 ip/ua/traceId；保留 3 年，可导出 CSV/JSON |
